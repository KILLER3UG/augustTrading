# Open items

The only working list. Each row is a measurement: the evidence column cites the code that proves
the row is still open, and the claim column says what is missing.

**Rules for this file.** A row closes by being deleted — git history is the record of what landed
and why (`git log --oneline -- docs/plan/open-items.md`), so a closed row here is a lie about the
present. An open question that needs the owner rides as its own row with both honest answers
sketched, not as a separate decision log. Paths are under `src/`; the line numbers inside the
`O-nn` text are the measurement at the commit the row was last re-measured, not a live claim —
re-measure before building from a row.

**Ids are provenance, not links.** `E-57 §3`, `QW5`, `06-independent-review`, `M-4`, `L-7`, `F-9`,
`stage3-status` and the rest name findings in the audit and research corpus, deleted on
2026-11-06. They say why a row exists. The code the evidence column cites is the live witness —
if it no longer says what the row claims, the row is stale: re-measure it or delete it.

**Superseded, 2026-11-06.** Skills are document folders and context only: `skills/<slug>/SKILL.md`
plus optional `references/ templates/ scripts/ assets/`, written by the model's `skill_write` or the
trader's library. The lifecycle, the approval queue, the win/loss ledger, the tentative channel, the
automatic writers, the evaluator and skill predicates/vetoes/confidence caps are not requirements.
Current behaviour and its limits: [the learning loop](../architecture/learning-loop.md) and
`src/services/learning/SkillFileService.ts` › `writeSkillFile`.
