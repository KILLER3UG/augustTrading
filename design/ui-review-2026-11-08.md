## Findings, ordered by risk

### F1 — Funding rate and countdown render as one string, and the funding bar is invisible

**Severity: high · Surface: Analyze (chart head) · [HEAD]**

`FundingCountdown` returns a fragment of two siblings — a text row and a 3px progress bar — and the
caller drops that fragment into a **flex row**:

- `src/components/trade/TradeView.tsx:224` — the text row is `flex items-baseline justify-between`.
  Its width is the sum of its children, so `justify-between` has no free space to distribute and the
  two spans touch.
- `src/components/trade/TradeView.tsx:230` — the bar (`data-testid="funding-bar"`, `mt-1 block
  h-[3px]`) is a flex sibling in that row with no width, so it resolves to **0×3px**.
- `src/components/trade/TradeView.tsx:941` — the outer wrapper is `hidden shrink-0 items-baseline
  gap-1.5 sm:flex` — a row, not a column. This is the root cause of both symptoms.

**Measured** (1440×900, live):

| element | x | width |
|---|---|---|
| funding `0.0055%` | 530 | 59 |
| countdown `05:02:56` | 589 | 62 |
| `funding-bar` | 657 | **0** |

The funding span ends at 589 and the countdown begins at 589 — **zero gap**, so the header reads
`0.0055%05:02:56`. The bar's own comment (`TradeView.tsx:231`) says its width is a data value, so it
is meant to be seen.

**Fix:** make the wrapper a column (`sm:flex-col`) and give the text row `w-full`, or move the bar
inside a column wrapper. One change fixes both.

### F2 — Verdict levels crush the chart's price scale

**Severity: high · Surface: Analyze (chart) · [HEAD]**

Each verdict level is added as its own `LineSeries`:

- `src/components/trade/TradingChart.tsx:648` — `chart.addSeries(LineSeries, {…})`
- `src/components/trade/TradingChart.tsx:657` — `line.setData([{…value: level.price}, {…}])`
- `src/components/trade/TradingChart.tsx:487` — `ts?.fitContent?.()` on first paint

`fitContent()` fits the data of **every** series, and there is no `autoscaleInfoProvider` anywhere in
the file to opt the level lines out. A verdict whose levels sit far from the current price therefore
zooms the chart out until the candles are unreadable.

**Evidence:** `probe:surfaces` capture `.probe-artifacts/surface-analyze.png` (seeded verdict: entry
84,210 / stop 83,100 / target 87,900; price 75,671). The y-axis spans **74,000–90,000**, the candles
are compressed into a thin strip at the bottom, and the three level lines float far above the price
action. A stale plan — logged hours or days earlier — is the realistic trigger.

**Fix:** give the level series an `autoscaleInfoProvider` returning `null`, or fit only the candle
series (`candlesRef.current` range) and leave the level lines outside the fitted range.

### F3 — `render-probe` fails on a clean HEAD

**Severity: high (gate integrity) · [HEAD]**

The probe's own gate is red:

```
RENDER PROBE FAILED — 1 check(s):
 • the sidebar runs the full height of the window — nothing is stacked above it
   — agents-rail top 0px, header above=true
```

- `scripts/render-probe.cjs:1999-2001` — the check is `nav.railTop === 0 && !nav.headerAbove`, where
  `headerAbove` is the proxy `!!document.querySelector('header')`.
- `src/components/agents/dock/AgentsDock.tsx:169` — the Agents workspace dock renders a semantic
  `<header>` for its panel (title, description, close).

Both the check and the header are in HEAD, so this fails on a clean checkout. The **layout is
correct**: measured at 1440×900, `agents-rail` is at `y=0, h=900` (full height) and the dock header is
at `x=1025, y=0, w=415, h=55` — inside the dock (`x=980, w=460`), not a band above the rail.

**Fix:** scope the proxy so it cannot see a panel header — e.g. assert the rail's `top === 0` and
that no `header` is an ancestor-or-previous-sibling spanning the shell width, rather than "no
`<header>` exists anywhere".

### F4 — `surface-shots` writes two mislabeled captures

**Severity: medium (gate integrity) · [HEAD]**

- `scripts/surface-shots.cjs:247` — navigates to the Skills tab by clicking
  `[data-testid="nav-customize"]`, a row that no longer exists. `scripts/render-probe.cjs:2750`
  asserts the opposite: *"the shell has no Customize row — Skills is a tab of Learning"*. The two
  gates disagree; `surface-shots` is the stale one.
- The failure cascades: `surface-shots.cjs:282` then presses `[data-testid="skills-catalog-card"]`,
  which does exist (`src/components/skills/SkillLibrary.tsx:342`) but is not on screen, so it also
  reports `missing`.

**Result:** `surface-learning-skills.png` and `ui-skill-reader.png` are both pictures of the **Agents
surface** (verified visually — chat thread, `Shot seeded`, rail chat icon highlighted). The script
logs `no Customize row` and keeps going, so the bad captures are written under names that claim
otherwise.

**Fix:** navigate to Learning and press `[data-testid="learn-tab-skills"]` (the same control the
probe's own comment describes), and make a failed navigation throw rather than re-shooting the
current surface.

### F5 — Inline code pills break mid-token

**Severity: medium · Surface: Learning → Memory (Pattern memory card), and any markdown answer**

- `src/components/shared/MarkdownRenderer.tsx:130` — the inline `code` pill class is
  `rounded-control border border-white/10 bg-white/[0.06] px-1 py-0.5 font-mono text-[12.5px] text-zinc-200`
  with no `whitespace-nowrap`.

Because an inline element paints its background once per line box, a long token splits into two
rounded bands. **Evidence:** in `.probe-artifacts/surface-learning.png` the pill
`` `rules/recurring-mistakes.md` `` renders as `rules/recurring-` on one line and `mistakes.md` on the
next, while the identical pill on the `See also:` line fits on one line.

**Fix:** add `whitespace-nowrap` (and `break-inside-avoid`) to the inline code class.
